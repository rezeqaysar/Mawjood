**أرشيف حياة الشخص والعائلة اليومية.**
- كل تسجيل = لحظة موثقة: الصوت الأصلي + النص + التاريخ + المتحدث + المساحة.
- مع الوقت: أرشيف يومي **قابل للسؤال** ("شو كنا نحكي قبل سنة؟") — منظّم (مهام/مواعيد/أماكن/مشتريات/وعود) وليس أرشيف نصوص خام.
- الميزة الدفاعية: قيمة الأرشيف **تتراكم** مع الاستخدام — بعد سنة مستحيل المستخدم يترك تطبيق فيه ذاكرة عيلته وصوت أحبته.
- الأرشيف هو **الرؤية**؛ الاستخدام اليومي ("وين أغراضي؟ شو مهامي؟") هو **المدخل** — الناس تشترك للمشكلة اليومية، والأرشيف يجعلها لا تغادر أبداً.
- ملامح مستقبلية: "بهذا اليوم قبل سنة/سنتين"، حفظ أصوات الأحبة، تاريخ العائلة عبر الأجيال.
- ملاحظة تقنية: الاحتفاظ بالصوت الأصلي ضروري للتوثيق ("إجابة بمصدر") — مع سياسة ضغط/أرشفة للملفات القديمة لضبط تكلفة التخزين.

## ✅ متفق عليها (جاهزة للتنفيذ)

### 1. زر تبديل بين إدخال صوتي ونصي
- عند إضافة ملاحظة: toggle بين 🎙️ مايك و ⌨️ نص.
- نفس الفكرة لميزة السؤال والجواب: سؤال صوتي أو كتابي.
- الهدف: الناس اللي بتحب تكتب والناس اللي بتحب تسجّل — الطريقتين مدعومتين.
- ملاحظة تقنية: النص المكتوب بيتخطى التفريغ الصوتي وبيروح مباشرة للاستخراج (extract).

### 2. السؤال والجواب (Q&A) — "وين المفك؟"
- المستخدم بيسأل صوتياً أو كتابةً، والتطبيق بيجاوب من الملاحظات المحفوظة.
- مثال: "وين حطيت المفك؟" ← "بالدرج الثاني بالمطبخ، سجّلتها يوم الثلاثاء."
- بيدعم الإدخال الصوتي والنصي (مرتبط بالفكرة رقم 1).
- ملاحظة تقنية: edge function جديدة (ask) — بحث دلالي/نصي بالملاحظات + gpt-4o-mini للإجابة.
- **معايير القبول** — أسئلة الاختبار (لازم يجاوب عليها كلها صح):
  - وين حطيت جواز السفر؟
  - آخر مرة اشتريت فلتر المكيف متى؟
  - شو مقاس الفلتر تبعي؟
  - وين فاتورة الأرضيات؟
  - شو الأشياء الموجودة في الكراج؟
  - متى صلحت السيارة؟
  - شو المنتجات الي جربتها وما عجبتني؟
  - شو الأشياء الي لازم أتذكرها قبل السفر؟

### 3. نقل ملاحظة بين المساحات — بزر أو بالسحب
- زر "انقل إلى…" على كل بطاقة ملاحظة بيفتح اختيار المساحة، **أو** ضغط مطوّل على البطاقة وسحبها (hold & drop) لتبويب المساحة الهدف.
- بينقل الملاحظة مع كل العناصر المستخرجة منها (مهام/مواعيد/مشتريات/أماكن).
- ملاحظة تقنية: تحديث `space_id` بجدولي notes و items (سياسات RLS بتسمح).

### 4. اقتراح تلقائي للمساحة حسب المحتوى
- التطبيق يقرأ محتوى الملاحظة (صوتية أو نصية) ويقترح المساحة المناسبة قبل الحفظ.
- مثال: "ذكّر الأولاد بموعد الأسنان" ← يقترح Family.
- ~~المستخدم بيأكد الاقتراح أو بيغيّره بكبسة.~~ **قرار المستخدم 23 سبتمبر 2026:** الذكاء يختار مباشرة بدون سؤال المستخدم — انشال منتقي المساحة اليدوي ("الحفظ في:") من الشات نهائياً. الملاحظة بتنزل بـ private أولاً (الأأمن)، والمصنف بينقلها تلقائياً.
- **مسار التطوير (2026-09-22):**
  1. **قواعد كلمات heuristic** (مبني ✅ بالمرحلة 1) — سريع، مجاني، يعمل بدون إنترنت.
  2. **تصنيف بالذكاء الاصطناعي** (المرحلة 2) — نفس الموديل الرخيص (gpt-4o-mini) يصنّف الملاحظة ويفهم السياق ("ابني" = عائلة حتى بدون كلمات مفتاحية). التكلفة أجزاء من السنت لكل ملاحظة.
  3. **ذاكرة الكيانات** (لاحقاً) — التطبيق يتعلّم **أشخاصك**: أول مرة "ابني اسمه كريم" ← يحفظ كريم (ابن، عائلة). بعدها أي ذكر لكريم = عائلة تلقائياً، بدون قواعد. هكذا تتراكم الذاكرة الحقيقية.
- **التنفيذ الفعلي (2026-09-23):** دالة `classify` هجينة بطبقتين — (1) قواعد دقيقة للحالات الواضحة (مشتريات/سوبرماركت ← عائلة، كلمات شغل ← شغل، نمط "اسم: مهمة" ← عائلة، مع تمييز "درج المكتب"=أثاث عن "المكتب"=شغل)، (2) الموديل للحالات الغامضة. نفس القواعد موجودة كـ fallback محلي في `suggest.ts` إذا انقطع الاتصال. نتيجة الاختبار: 10/10.

### 5. 📍 صورة للمكان — "وين أغراضي؟" بدليل بصري
- عند تسجيل مكان غرض: إمكانية إرفاق صورة (صوّر الدرج/الرف).
- لما تسأل "وين المفك؟" الجواب بيعرض الصورة مع المكان — موثوقية 100%.
- ملاحظة تقنية: رفع الصورة لـ Supabase Storage وربطها بعنصر الـ place.

### 6. "مين أخذها؟" — تتبع الاستعارة ✅ (مبني + مفحوص 2026-09-23)
- "أحمد أخذ المفك" ← صف بجدول borrows (migration 0012) + اسم الشخص + تاريخ الإرجاع إن ذُكر.
- لما تسأل وين المفك: "المفك مع أحمد — أخذه بتاريخ …".
- بتضرب الركيزتين معاً: أين أشيائي + العائلة.
- التنفيذ: extract يستخرج أحداث lend/return؛ الشات: مسار سريع حتمي لـ"رجع X" + أداة return_borrow للوكيل + البحث يشمل الاستعارات المفتوحة؛ تبويب 📦 أشيائي يعرض شارة "🤝 مع أحمد" + زر "✅ رجع" بتأكيد مزدوج.

### 7. إجابات بمصدر موثق
- كل جواب "وين" بيورجي الملاحظة الأصلية: مقطع الصوت + تاريخ التسجيل.
- ثقة ضد هلوسة الذكاء الاصطناعي، وتكلفة تنفيذ منخفضة (البيانات موجودة أصلاً).
- ⚠️ **قرار المستخدم 23 سبتمبر 2026:** إزالة عرض المصادر من فقاعات الشات — كانت تعمل زحمة. البيانات بتضل موجودة بالـ backend، بس العرض بالشات انشال.

### 11. أنواع استخراج جديدة (لخدمة Q&A)
- **مواصفات** (specs): "مقاس الفلتر 20x25x1" ← تجاوب "شو مقاس الفلتر تبعي؟"

- **قوائم تحقق** (checklists): "قبل السفر: جواز، شاحن، دوا" ← تجاوب "شو لازم أتذكر قبل السفر؟"
- ملاحظة تقنية: توسيع extract function + kinds جديدة بجدول items.

### 12. 🔄 مدخل موحّد + حلقة التصحيح الحوارية (مبني 2026-09-23)
- **مدخل واحد ذكي** (صوت/نص): سؤال ← جواب فوري، جملة عادية ← ملاحظة. السؤال لا يُحفظ كملاحظة.
- **حلقة التصحيح**: بعد "وين جوازي؟ ← بالجرار"، لو قال "لا، نقلته على الخزانة" ← التطبيق يحدّث مكان الغرض **فوراً** ويأكد "✅ تم التحديث".
- هكذا تُبنى **ذاكرة أماكن حيّة** لكل غرض — الداتا اللي بيحتاجها "المحقق" 🛡️🔍 لاحقاً (احتمالات الأماكن مرتبة حسب آخر المشاهدات).

### 13. 💬 الرئيسية شات-first (مبني 2026-09-23) — قرار المنتج: "ما بدنا عجقة"
- **الرئيسية = شات فارغة** بنظام الفقاعات: تعرض النتائج فقط (فقاعة المستخدم + فقاعة التطبيق)، وما فيها قوائم ملاحظات.
- **المساحات (Private/Family/Work) تُستعرض فقط لما تكبس عليها** — فيها البحث والبطاقات والنقل بين المساحات.
- **الشات بيتفرّغ لما اليوزر يطلع من التطبيق** (AppState background) — البيانات محفوظة على السيرفر وتطلع بالمساحات والبحث.
- الأسئلة في الشات تُسأل **عبر كل المساحات** (مش مساحة واحدة) — لأن المستخدم وهو بيسأل "وين جوازي؟" ما بيهمه بأي مساحة انحفظ.
- ملاحظة الصوت بعد التفريغ: ~~لو الاقتراح التلقائي للمساحة مختلف عن اللي اختارها ← فقاعة "💡 هاي بتناسب مساحة X — أنقلها؟ [نقل/إبقاء]".~~ **ملغى:** الذكاء بيختار المساحة مباشرة (فكرة 4).

### 14. 🧠 توجيه الإدخال بالذكاء مع ذاكرة محادثة (مبني 2026-09-23) — "يجاوب زي ChatGPT"
- **المشكلة:** التوجيه (سؤال/ملاحظة/تصحيح) كان ريجكس على التلفون بكلمات ثابتة — "وينتا موعدي عند المحامي" انحفظت كملاحظة بدل ما تتجاوب، و"انا سالتك متى الموعد ما حكيتلك تضيفها" انحفظت كمان.
- **الحل:** دالة `route` جديدة على السيرفر — الموديل بيقرر (سؤال/ملاحظة/تصحيح + المساحة) **مع آخر 6 رسائل من المحادثة** كسياق، مش كل رسالة لحالها.
- **ذاكرة المحادثة بالأسئلة:** دالة `ask` صارت تستقبل سجل المحادثة — أسئلة المتابعة ("وينتا؟") بتنفهم من السياق.
- **أمان:** لو الدالة فشلت، fallback محلي (ريجكس محسّن + كلمات لهجة: وينتا/ايمتى/وقتاش/قديش) — التطبيق ما بيوقف أبداً.

### 15. 🧠 العقل الموحد — وكيل بأدوات (مبني 2026-09-23) — "كأني بحكي مع شات حي"
- **الفكرة:** بدل دوال منفصلة (route/ask/classify/extract)، دالة `chat` وحدة: الموديل بيفكر وبستعمل أدوات (search, get_agenda, save_note, delete_note, move_note, update_item) بحلقة ReAct حتى 5 خطوات، وبعدين بيجاوب.
- **المسار:** النص والصوت بيمرّوا بنفس العقل؛ لو الوكيل فشل، fallback تلقائي للمسار القديم (route→ask) — التطبيق ما بيوقف.
- **دروس من الاختبار الحي:** (1) أعطِ الوكيل الـ ids الكاملة مش المختصرة — الأدوات ما بتشتغل بالمختصر؛ (2) بأسئلة "وين حطيت" غرض المكان (kind=place) هو مصدر الحقيقة مش نص الملاحظة القديمة؛ (3) عند التصحيح حدّث كل النسخ المكررة؛ (4) Groq المجاني 429 تحت الضغط — الدالة بتعيد المحاولة مرة وحدة.
- **مُختبَر حي:** حفظ ← سؤال ← تصحيح ("لا، نقلته على الخزانة") ← سؤال مرة ثانية = "بالخزانة" ✅.

### 16. 🌐 موقع مستقبلي — إدارة المخازن السرية (فكرة 2026-09-24، للتنفيذ لاحقاً)
- **الفكرة (من المستخدم):** صفحة على موقع التطبيق المستقبلي: المستخدم بيدخل إيميله + باسورد المخزن، ومن هناك بيغيّر باسورد المخزن — "هيك اكثر امان".
- **التعديل الأمني المهم:** إيميل مكتوب يدوياً ≠ تحقق. أي حد بيعرف الكلمة بيقدر يكتب أي إيميل. التصميم الصح: تسجيل دخول بنفس حساب التطبيق (magic link على إيميل الحساب — هوية موثقة فعلاً) ← بعدها إدارة المخازن: عرض المخازن (مخزن ١، ٢…)، تدوير كلمة (اختياري: طلب الكلمة الحالية)، حذف مخزن. التطبيق على التلفون يضل بلا أي واجهة إدارة (opsec: لا أثر).
- **اعتبار إضافي للمستقبل:** تخزين الأكواد كـ hash (bcrypt) بدل نص صريح — حتى تسريب قاعدة البيانات ما بيكشف الأكواد؛ اعتراض الشات بيقارن الـ hash. حالياً plaintext (مقبول: RLS صارم + مجهولية).
- **"المفتاح الشبح" 👻 (تصميم 2026-09-24 — رد على: "مش أي حد بالبيت يمسك التلفون يفوت عالإدارة"):** مفتاحان منفصلان —
  - **كلمة المخزن:** بتفتح مخزنها وبس (الوضع الحالي، ما بيتغير).
  - **المفتاح الرئيسي (master key):** وحده بيفتح **الإدارة** (عرض/تغيير/حذف المخازن). يُنشأ مرة وحدة، يُعرض مرة وحدة، يُحفظ **براس المالك بس** — لا بالتلفون، لا بقاعدة البيانات (بس بصمته bcrypt للمقارنة)، لا بالإيميل.
  - **بوابة الموقع = طبقتان:** magic link (إثبات ملكية الحساب) **+** المفتاح الرئيسي (إثبات إنك المالك مش حد فاتح إيميلك على نفس التلفون). حتى لو حد مسك تلفونك **و** إيميلك **و** عرف كلمة مخزن → بيفتح هالمخزن بس، ما بيشوف الباقي ولا بيغيّر ولا بيحذف.
  - **جرس الإنذار:** كل محاولة دخول على الإدارة (ناجحة أو فاشلة) → push فوري لكل أجهزة المالك + إيميل. حد جرّب الساعة ٢ بالليل؟ بتعرف فوراً.
  - **ضد التخمين:** ٥ محاولات غلط → قفل ساعة كاملة.
  - **الاسترداد (لو نسيت المفتاح):** magic link + **٧ أيام انتظار** + إشعار فوري لكل أجهزتك، وبتقدر تلغي الاسترداد بأي لحظة من التطبيق. السارق ما بيقدر يستعمله بصمت، والمالك ما بينحبس برا مخازنه.
  - **بونص سينمائي (اختياري):** كلمة طوارئ وهمية بتفتح مخزن فاضي شكله حقيقي — وبالسر بتبعتلك تنبيه صامت إن حد أجبرك تفتح 😄🎬
- **بصراحة:** ما في ضمان ١٠٠٪ بأي نظام، بس هيك المهاجم محتاج ٣ شغلات مع بعض (التلفون + الحساب + سر براسك)، ووحدة منهم ما بتنسرق من أي جهاز.
